# Validation decorations — deferred follow-ups (from PR #58 bot review triage)

Deliberately not addressed in v0.14.0 to keep the feature lean; revisit when the need shows up in practice.

- **Cross-domain `pipeCode` collisions** (cubic, `validationIssues.ts`): a `pipe.<code>` diagnostic path carries no domain, and `buildValidationDecorations` matches by bare `pipe_code`, so in a merged multi-domain method set two pipes sharing a code in different domains would decorate each other's nodes. Real but narrow: parse/normalize diagnostics are emitted per-bundle where the code is unambiguous, and same-code-different-domain bundles are rare. Fix shape if needed: add an optional `domainCode` targeting field to `ValidationIssue`, fill it in the mapper (each bundle knows its domain), and match `pipe_code` + `domain_code` when present.
- **Auto-collapse roll-up** (cubic, `graphValidation.ts`): `applyControllers` hides children beyond `MAX_VISIBLE_CONTROLLER_CHILDREN` for collapsed Parallel/Batch groups; decorations targeting those hidden children disappear from the graph (they stay in the panel). Folding — the primary mechanism — does roll up. Fix shape if needed: mirror the fold roll-up for collapse-hidden targets, which requires exposing the collapse-hidden set from `applyControllers`.
- **`GraphToolbar` uncontrolled fallback** (cubic): the dropdown open state is now controlled (`validationOpen`/`onValidationOpenChange`); a direct `GraphToolbar` consumer that passes `validationState` but no open-state props gets a dead toggle. Decided against a dual controlled/uncontrolled mode — `GraphToolbar` is effectively internal to `GraphViewer`, and the breaking change is documented in the changelog.
